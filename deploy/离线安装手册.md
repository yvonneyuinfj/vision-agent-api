# 园区网离线安装手册（正向流程）

> **适用环境**：中科方德 NFC Server 4.0 x86_64，glibc 2.28，systemd 239，OpenSSL 1.1.1k，禁 Docker
> **前提**：Python 3.11 已离线编译安装至 `/usr/local/bin/python3.11`；libaio 已在 `/lib64`
> **制品包**：`offline-bundle/`（含 source.tar.gz、qcagent-venv.tar.gz、MySQL 8.0.46 minimal、mc/minio、SHA256SUMS.txt 等）
> **规范路径**：`APP_DIR=/opt/agent/vision-agent/quality-agent`（venv 迁移要求验证机与目标机此路径一字不差）
> **监听端口**：`18000`（高位端口 ≥1024，非 root 直接可绑，免 setcap/AmbientCapabilities 提权）

## 阶段 2 · MySQL 8.0.46 裸装

> MySQL 必须早于平台启动；官方 generic minimal tarball（glibc2.17 构建），唯一系统依赖 libaio；bind-address=127.0.0.1，账号 host 收敛。

```bash
# 2.1 解压 + 创建用户
cd /usr/local && tar -xf /root/offline-bundle/mysql-8.0.46-linux-glibc2.17-x86_64-minimal.tar.xz
ln -sfn mysql-8.0.46-linux-glibc2.17-x86_64-minimal /usr/local/mysql
useradd -r -s /sbin/nologin mysql 2>/dev/null || echo "mysql 用户已存在"
mkdir -p /var/lib/mysql /var/log/mysql
chown -R mysql:mysql /usr/local/mysql /var/lib/mysql /var/log/mysql

# 2.2 修复 libncurses 依赖（MySQL 客户端需要 ncurses 5，系统只有 6）
ln -s /lib64/libncurses.so.6 /lib64/libncurses.so.5
ln -s /lib64/libtinfo.so.6 /lib64/libtinfo.so.5
ldconfig
/usr/local/mysql/bin/mysql --version  # 应显示 Ver 8.0.46

# 2.3 初始化数据目录（--initialize-insecure 不设 root 密码，后续手动设）
/usr/local/mysql/bin/mysqld --initialize-insecure --user=mysql --basedir=/usr/local/mysql --datadir=/var/lib/mysql

# 2.4 创建 systemd 单元
cat > /etc/systemd/system/mysqld.service <<'EOF'
[Unit]
Description=MySQL 8.0.46 (bare install)
After=network.target

[Service]
User=mysql
Group=mysql
ExecStart=/usr/local/mysql/bin/mysqld --basedir=/usr/local/mysql --datadir=/var/lib/mysql --bind-address=127.0.0.1
ExecStop=/usr/local/mysql/bin/mysqladmin -u root shutdown
Restart=on-failure
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable mysqld
systemctl start mysqld
systemctl status mysqld --no-pager -l | head -10

# 2.5 设 root 密码 + 建库建账号
/usr/local/mysql/bin/mysql -u root -e "ALTER USER 'root'@'localhost' IDENTIFIED BY 'QcAgent@2026'; FLUSH PRIVILEGES;"
echo 'QcAgent@2026' > /opt/qc-mysql-root.pass && chmod 600 /opt/qc-mysql-root.pass

# 改 qc_agent 密码（避免用 <CHANGE_ME> 字面量）
/usr/local/mysql/bin/mysql -uroot -p'QcAgent@2026' -e "ALTER USER 'qc_agent'@'%' IDENTIFIED BY 'QcAgent@DB2026'; FLUSH PRIVILEGES;"

# 建库 + 授权
/usr/local/mysql/bin/mysql -uroot -p'QcAgent@2026' < /root/QualityCheckingAgent/scripts/sql/init.sql
/usr/local/mysql/bin/mysql -uroot -p'QcAgent@2026' < /root/QualityCheckingAgent/deploy/sql/create_platform_user.sql

# 2.6 验证
/usr/local/mysql/bin/mysql -uroot -p'QcAgent@2026' -e "SHOW DATABASES; SELECT user, host FROM mysql.user WHERE user NOT LIKE 'mysql.%';"
```

**预期**：显示 `quality_inspection` 库 + `qc_agent@%` 账号。

## 阶段 4 · venv 路径修正（关键！）

> **原因**：venv 打包时 shebang 可能指向旧裸路径（`/opt/agent/vision-agent/.venv`），需修正为规范路径（`/opt/agent/vision-agent/quality-agent/.venv`），否则 systemd 启动报 `203/EXEC`。

```bash
# 4.1 批量修正 venv 脚本 shebang
find /opt/agent/vision-agent/quality-agent/.venv/bin -type f \
  -exec grep -l '^#!/opt/agent/vision-agent/.venv/bin/python' {} \; \
  | xargs sed -i 's|^#!/opt/agent/vision-agent/.venv/bin/python|#!/opt/agent/vision-agent/quality-agent/.venv/bin/python|'

# 4.2 修正 pyvenv.cfg
sed -i 's|/opt/agent/vision-agent/.venv|/opt/agent/vision-agent/quality-agent/.venv|g' \
  /opt/agent/vision-agent/quality-agent/.venv/pyvenv.cfg

# 4.3 验证
head -1 /opt/agent/vision-agent/quality-agent/.venv/bin/uvicorn
cat /opt/agent/vision-agent/quality-agent/.venv/pyvenv.cfg | grep -E 'home|executable'
```

**预期**：uvicorn shebang 指向 `/opt/agent/vision-agent/quality-agent/.venv/bin/python`；pyvenv.cfg 的 `home` 和 `executable` 指向规范路径。

## 阶段 5 · 配置 .env

> **注意**：
> - 值后面**不要**写行内注释（systemd EnvironmentFile 会把注释当值的一部分）
> - 密码避开 `# & $` 等 systemd/shell 敏感字符
> - DATABASE_URL 中密码若含 `@`，必须 URL-encode 为 `%40`
> - MINIO endpoint 格式 `host:port`，**不带** `http://` 前缀

```bash
# 5.1 复制园区网底稿
cp /root/QualityCheckingAgent/deploy/env.园区网.example /opt/agent/vision-agent/quality-agent/.env
chmod 600 /opt/agent/vision-agent/quality-agent/.env
chown qcagent:qcagent /opt/agent/vision-agent/quality-agent/.env

# 5.2 用 Python 批量替换占位符（sed 对中文占位符匹配不稳定，改用 Python）
python3 <<'PYEOF'
path = '/opt/agent/vision-agent/quality-agent/.env'
with open(path, 'r', encoding='utf-8') as f:
    content = f.read()

replacements = {
    '<平台专用密码>': 'QcAgent@DB2026',
    '<登录账号，如 qcadmin>': 'qcadmin',
    '<登录密码，覆盖默认随机值>': 'QcAgent@Web2026',
    '<会话签名密钥，随机串，务必与默认不同>': 'drill-secret-key-2026',
    '<所内RAGFlow_IP>': '127.0.0.1',
    '<RAGFLOW_API_KEY>': 'drill-ragflow-key',
    '<所内Ceph_RGW_IP>:<端口>': '127.0.0.1:9000',
    '<Ceph_ACCESS_KEY>': 'drill-minio-access',
    '<Ceph_SECRET_KEY>': 'drill-minio-secret',
    '<网关密钥；无鉴权则填占位串 non-secret>': 'non-secret',
    '<所内文本模型名，如 qwen2.5-72b-instruct>': 'qwen2.5-72b-instruct',
    '<所内视觉模型名，如 qwen2.5-vl-72b；无则留空>': '',
    'http://<网关IP>:<端口>/v1': 'http://127.0.0.1:18080/v1',
}
for k, v in replacements.items():
    content = content.replace(k, v)

# MINIO 留空降级本地落盘（演练/无 Ceph 环境）
content = content.replace('MINIO_ENDPOINT=127.0.0.1:9000', 'MINIO_ENDPOINT=')
content = content.replace('MINIO_ACCESS_KEY=drill-minio-access', 'MINIO_ACCESS_KEY=')
content = content.replace('MINIO_SECRET_KEY=drill-minio-secret', 'MINIO_SECRET_KEY=')

with open(path, 'w', encoding='utf-8') as f:
    f.write(content)
print('Done')
PYEOF

# 5.3 URL-encode DATABASE_URL 密码中的 @ 符号（必须，否则解析器把 @ 后内容当 host）
sed -i 's|qc_agent:QcAgent@DB2026@|qc_agent:QcAgent%40DB2026@|' /opt/agent/vision-agent/quality-agent/.env

# 5.4 验证无残留占位符
grep '<' /opt/agent/vision-agent/quality-agent/.env | grep -v '^#' || echo 'OK 无占位符'
grep -E '^(AUTH_|DATABASE_URL|API_PORT)=' /opt/agent/vision-agent/quality-agent/.env
```

**预期**：第一条输出 `OK 无占位符`；第二条显示 AUTH_USERNAME=qcadmin、DATABASE_URL 含 `QcAgent%40DB2026`、API_PORT=18000。

## 常见陷阱速查

| 症状 | 原因 | 修复 |
|------|------|------|
| `libncurses.so.5: cannot open shared object file` | MySQL 客户端依赖 ncurses 5，系统只有 6 | `ln -s /lib64/libncurses.so.6 /lib64/libncurses.so.5` + `ln -s /lib64/libtinfo.so.6 /lib64/libtinfo.so.5` + `ldconfig` |
| `status=203/EXEC`（systemd） | venv shebang 指向旧裸路径 | 批量修正 `.venv/bin/*` 的 shebang + `pyvenv.cfg`（阶段 4） |
| `Can't connect to MySQL server on 'DB2026@127.0.0.1'` | DATABASE_URL 密码含 `@` 未 URL-encode，解析器把 `@` 后内容当 host | `sed -i 's\|:QcAgent@DB2026@\|:QcAgent%40DB2026@\|' .env` |
| MinIO 连接重试阻塞启动 | 演练环境无 Ceph/MinIO | MINIO_ENDPOINT/ACCESS_KEY/SECRET_KEY 三行留空，降级本地落盘 `data/` |
| sed 替换中文占位符失败 | 编码/转义问题 | 改用 Python `str.replace()`（阶段 5.2） |
| `source.tar.gz` 泄漏 `.env`（含真实密钥） | 打包时未排除 | tar 命令必须含 `--exclude='.env' --exclude='.env.local'`；打包后 `tar -tzf ... \| grep '\.env'` 复查 |
| `uv export` 生成的 `requirements-offline.txt` 含 `-e .` 行 | uv 默认将项目自身以可编辑安装写入 | `sed -i '/^-e /d' requirements-offline.txt`，否则 `pip download` 整批崩溃 |
| `rpm -qa` 显示"未安装"但实际已装 | 中文系统 locale 陷阱 | 改用 `ls /usr/include/xxx.h` 头文件判据 |
| 离线制品包被 `rsync --delete` 误删 | 制品包放在 APP_DIR 内 | 制品包必须放 APP_DIR 之外（如 `/root/offline-bundle`） |

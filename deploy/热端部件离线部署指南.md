> **capability_id**：`infrared_defect_detection_v1`（平台 scene = `infrared`）

## 3. 部署前必修项（★ 不做这步 install_offline.sh 必挂）

### 3.1 放宽 Python 版本校验

交付包 `check_environment.sh` 第 49 行**硬编码** `(3, 11, 16)`，会拒绝 3.11.14（服务器既有版本）。  
修复（仅改 minor 匹配，不动 patch）：

```bash
cd /opt/agent/vision-agent/tools/hotsection/hot_end_api_offline_cpu_20260917_rev3
sed -i 's/sys.version_info\[:3\] == (3, 11, 16)/sys.version_info[:2] == (3, 11)/' check_environment.sh
```

### 3.2 更新被修改文件的校验哈希

`install_offline.sh` 的 `[2/7]` 步用 `sha256sum -c SHA256SUMS.txt` 验证所有文件完整性。  
改过 `check_environment.sh` 后哈希不匹配 → **必须更新**：

```bash
# 删除旧行，追加新哈希
grep -v 'check_environment.sh' SHA256SUMS.txt > SHA256SUMS.txt.tmp
sha256sum check_environment.sh >> SHA256SUMS.txt.tmp
mv SHA256SUMS.txt.tmp SHA256SUMS.txt
```

### 3.3 处理中文文件名 GBK 乱码

**症状**：`install_offline.sh` 第 `[2/7]` 步 `sha256sum -c` 报 `.docx` / `.md` 等文件"无法打开"。  
**根因**：交付方在 Windows 打包 zip，中文文件名按 GBK 编码；服务器 unzip 6.00 默认按 cp437 解码 → 乱码。

**方案 A（推荐）：用 Python 重新解压覆盖**

```bash
cd /opt/agent/vision-agent/tools/hotsection
python3.11 -c '
import zipfile, os
zf = zipfile.ZipFile("hot_end_api_offline_cpu_20260917_rev3.zip")
for info in zf.infolist():
    name = info.filename
    try:
        fixed = name.encode("cp437").decode("gbk")
    except (UnicodeDecodeError, UnicodeEncodeError):
        fixed = name
    target = os.path.join(".", fixed)
    if info.is_dir():
        os.makedirs(target, exist_ok=True)
    else:
        os.makedirs(os.path.dirname(target), exist_ok=True)
        with zf.open(info) as src, open(target, "wb") as dst:
            dst.write(src.read())
print("重解压完成 ✅")
'
```

> **注意**：需把原始 zip 文件也放到 `/opt/agent/vision-agent/tools/hotsection/` 下执行（或改脚本里的路径）。

**方案 B（快速绕过）：从 SHA256SUMS 剔除文档类条目**

文档（.docx/.md/.pdf）不在运行路径上，缺失不影响服务。若乱码只涉及文档：

```bash
sed -i '/\.docx\|\.md\|\.pdf/d' SHA256SUMS.txt
```

> ⚠️ 仅限**非 wheels/ 非代码文件**。若 `wheels/*.whl` 或核心代码乱码，必须用方案 A 重解。

## 7. systemd 配置（生产常驻）

```bash
cat > /etc/systemd/system/ai-tool-hotsection.service <<'EOF'
[Unit]
Description=AI tool: hotsection (热端部件故障诊断)
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/agent/vision-agent/tools/hotsection/hot_end_api_offline_cpu_20260917_rev3
Environment=PYTHONUNBUFFERED=1
ExecStart=/opt/agent/vision-agent/tools/hotsection/hot_end_api_offline_cpu_20260917_rev3/venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 18015
Restart=on-failure
RestartSec=5
StandardOutput=journal
StandardError=journal
SyslogIdentifier=ai-tool-hotsection

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now ai-tool-hotsection
systemctl status ai-tool-hotsection
```

> **WorkingDirectory 很重要**：Uvicorn 启动 FastAPI 时，相对路径导入（`app.main`）基于 cwd 解析。  
> `WorkingDirectory` 必须设为含 `app/` 子目录的那个路径。

## 13. 故障排查速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `install_offline.sh` 报 Python 版本不匹配 | `check_environment.sh` 硬编码 3.11.16 | §3.1 sed 修复 |
| `sha256sum -c` 报 `check_environment.sh: FAILED` | 改文件后未更新哈希 | §3.2 更新 SHA256SUMS |
| `sha256sum -c` 报 `.docx: 无法打开` | 中文文件名 GBK 乱码 | §3.3 方案 A 重解压 或 B 剔除 |
| `ImportError: liblapack.so` / `libgomp.so` | 缺系统库 | `yum install -y lapack libgomp` |
| uvicorn `Could not import module "app.main"` | 模块路径/WorkingDirectory 错 | `find . -name main.py`；确认 cwd 下有 `app/` |
| 启动即退出 / OOM | 内存不足（PyTorch ~2.5 GB） | 确认 `free -h` 可用 > 3 GB |
| 推理极慢（>30s）或报 `CUDA` | torch 装了 GPU 版 | 确认用 `2.1.2+cpu`（`+cpu` 后缀） |
| `Address already in use: 18015` | 端口被 mock 或旧进程占 | `fuser -k 18015/tcp` 后重启 |
| /health 返回但无 `tool_name` 中文名 | 仍在跑 mock | 停 mock 后重启真实服务 |

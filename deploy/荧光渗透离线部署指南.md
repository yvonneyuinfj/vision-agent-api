# 荧光渗透（Fluorescence / FPI）裸机离线部署指南

> **工具**：叶片缺陷检测 API (blade_defect_detector / thread-defect-api)  
> **端口**：18016  
> **部署形态**：裸机 venv + systemd（**非容器**，需裁剪 glibc 2.28 不兼容依赖后安装）  
> **模型**：YOLOX-S（tile 1024）+ PyTorch 2.1.2+cpu，CPU-only，~10s/图  
> **框架**：FastAPI + Uvicorn  
> **目标环境**：x86_64 / Python 3.11.x / NFS Server 3.1 (glibc 2.17)  
> **capability_id**：`fpi_defect_detection_v1`（平台 scene = `fpi`）  
> **交付包**：`thread-defect-api-20260910`  
> **权重 SHA256**：`4F2CA9AB07761C54973F90844B02E6B72C1BB095F91EB25AE999E55422C631C2`  
> **响应外壳**：**非规范 `data` 包裹** → 平台 `tool_profiles.py` 归一，部署前必须确认 §7 四文件已同步

### 2.2 判定方法（对新工具通用）

```bash
# 看交付包 wheel 文件名的最高 manylinux 标签
ls wheels/ | grep -oP 'manylinux_\K[0-9]+' | sort -rn | head -1
# 若 ≥ 28 → 需要降级或裁剪该包
```

## 5. 关键适配：YOLOX 源码 PYTHONPATH 直挂

**问题**：交付方用 `pip install -e .` 安装 YOLOX + 预编译 `FastCOCOEvalOp`。  
服务器 gcc 4.8.5 **无法编译** torch 2.1.2 的 C++17 扩展 → `setup.py` 必定失败。

**方案**：不安装 YOLOX 到 site-packages，改用 PYTHONPATH 源码挂载。  
`start.sh` 中已固化：

```bash
export PYTHONPATH="$APP/labels/yolox_project/YOLOX:$APP/labels/yolox_project${PYTHONPATH:+:$PYTHONPATH}"
```

**验证**（模型不加载时先查这一步是否生效）：
```bash
/opt/agent/vision-agent/tools/fluorescence/.venv/bin/python -c "import sys; sys.path.insert(0,'/opt/agent/vision-agent/tools/fluorescence/app/thread-defect-api-20260910/labels/yolox_project/YOLOX'); import yolox; print(yolox.__version__)"
# 应输出：0.3.0
```

> `FastCOCOEvalOp` 仅 COCO 评估脚本用到，推理路径已用 try/except 兜底，不装不影响服务。

### 6.2 systemd 单元（per-tool，本机实际用法）

> ⚠️ **不要用模板单元 `ai-tool@fluorescence`**（systemd 219 的 `%i` 展开 bug → `203/EXEC`）。  
> 正确单元名 = **`ai-tool-fluorescence.service`**。

```bash

[Unit]
Description=AI tool: fluorescence (叶片缺陷检测)
After=network.target

[Service]
Type=simple
User=root

Environment=PYTHONUNBUFFERED=1
ExecStart=/opt/agent/vision-agent/tools/fluorescence/start.sh
Restart=on-failure
RestartSec=5
StandardOutput=journal
StandardError=journal
SyslogIdentifier=ai-tool-fluorescence

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now ai-tool-fluorescence
journalctl -u ai-tool-fluorescence -f   # 观察模型加载（约 15-60s）
```

## 7. 平台侧前置依赖：响应归一四文件同步（★ 必做）

荧光交付包返回 **`data` 外壳**（非规范顶层 `result`），需平台 `tool_profiles.py` 做归一。

**四个文件必须先同步到服务器 `/opt/agent/vision-agent/quality-agent/`**：

| 文件 | 作用 |
|---|---|
| `app/capabilities/adapters/tool_profiles.py` | `transform_blade_defect_detector`（data → result 归一） |
| `app/capabilities/adapters/http_adapter.py` | 归一钩子 + 图片 MIME 按扩展名派生 |
| `app/agents/tools/infer_tool.py` | 产物本地化支持绝对 URI |
| `tests/capabilities/test_tool_profiles.py` | 10 个归一单测 |

同步后：
```bash
systemctl restart quality-agent
# 服务器跑测试确认：
cd /opt/agent/vision-agent/quality-agent && .venv/bin/pytest tests/capabilities/ -q
```

**归一逻辑核心**：
- `data.detections[]` 中 class_id ∈ {0:BP, 1:SP} → `result.defects[]`
- class_id = 2 (FI 虚假荧光) → 不计入真缺陷，仅 `false_indication_count++`
- `data.business_decision`：`unqualified` → `status=abnormal`；`qualified` → `status=normal`
- severity 不提供（不伪造，defect_normalizer 契约）
- 产物 URI 保留原样（4 类：original_image / result_image / result_json / report_pdf）

## 9. 接入平台（切端点）

### 9.1 切换命令（meta_json **必须给全量**）

```bash
bash /root/QualityCheckingAgent/deploy/switch_tool_endpoint.sh \
  fpi_defect_detection_v1 \
  http://127.0.0.1:18016 http://127.0.0.1:18016/health \
  '{"families":["defect"],"default_params":{"part_id":"UNKNOWN","device_id":"QC-PLATFORM"},"input_required":{"images":1,"image_field":"image"},"max_images":1,"note":"真实工具 blade_defect_detector（荧光渗透 thread-defect-api-20260910，/opt/agent/vision-agent/tools/fluorescence :18016）；parameters 仅 part_id/device_id/timestamp；响应归一 tool_profiles.py"}'
systemctl restart quality-agent
```

> ⚠️ **荧光参数模型使用 `extra=forbid`**（Pydantic）：  
> 任何不在 `parameters` 模型中声明的字段都会触发 422/1001。  
> `meta_json.default_params` **必须精确为** `{"part_id":"UNKNOWN","device_id":"QC-PLATFORM"}`  
> （`part_id` 兜底 UNKNOWN，不传 `timestamp`；多余字段会导致平台调用 422）。

智能检测 → 选择"荧光渗透检测"场景 → 上传荧光渗透图 → 任务完成 → 归一 6 条缺陷（BP/SP 带 bbox）+ 判级 `defect` + 报告四产物引用 = **第四个真实模型上线**。

## 10. 接口契约速查

| 项目 | 说明 |
|---|---|
| 接口 | `GET /health`、`POST /api/v1/inference` |
| 辅助 | `GET /docs`（Swagger）、`/`（检测页面）、产物资源路由 |
| 入参 | multipart：`image`(文件) + `task_id`(字符串) + `parameters`(JSON 字符串) |
| parameters 字段 | **仅允许** `part_id`(必填)、`device_id`(可选)、`timestamp`(ISO 8601,可选)。`extra=forbid` |
| 图片限制 | JPG/JPEG/PNG/BMP，≤ 20 MB |
| 成功响应 | HTTP 200 + `code:0` + `data.detections[]` + `data.business_decision` + `data.artifacts[]` |
| 认证（生产） | `X-API-Key: <密钥>`；服务器回环实例不启用 |
| 产物 URI | 带 HMAC 签名（无签名 401） |

### 错误码表（★ 与规范偏差，需平台侧映射）

| 工具码 | 工具含义 | HTTP 状态 | 平台映射 |
|---|---|---|---|
| 0 | 成功 | 200 | 正常流程 |
| 1001 | parameters JSON 非法/缺 part_id | 422 | 参数错误 |
| 1002 | Content-Type 不支持 | 415 | 格式错误 |
| 1003 | 图片不可读 | 400 | **≠规范**（规范 1003=超大） |
| 1004 | 图片超过 20MB | 413 | **≠规范**（规范无 1004） |
| 2001 | 模型未加载 | 503 | **≠规范**（规范 2001=参数非法） |
| 4001 | API 认证失败 | 401 | **≠规范**（规范 4001=内部错误） |

> 平台按 HTTP 状态码映射错误分类（413/415/422/503 语义与工具一致），不受码值偏差影响。

| 8 | 错误码语义 | 规范映射 | 工具自定义（1003/1004/2001/4001） | 平台按 HTTP 状态映射，分类不受影响 |

| 10 | pycocotools | 在主清单 | **二阶段 --no-deps** | matplotlib 冲突；漏装→degraded |
| 11 | systemd | ai-tool@<tool> | **per-tool ai-tool-fluorescence.service** | 219 模板 %i bug → 假绿 |

## 13. 故障排查速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `/health` 返回 `model.loaded: false` | pycocotools 未装（§4.4 漏做） | 补装 nodeps + restart |
| `/health` 返回 `model.loaded: false` | YOLOX PYTHONPATH 未生效 | 检查 start.sh 里 `PYTHONPATH` 两路径是否存在 |
| 推理返回 code 2001 | 模型未加载（同上） | 修复后 restart |
| install_ai_tool 显示 "health OK" 但载荷是 mock | **假绿**：旧 mock 占着端口应答 | `journalctl -u ai-tool@fluorescence` 看是否 203/EXEC；改用 `systemctl restart ai-tool-fluorescence` |
| `systemctl status ai-tool@fluorescence` 报 203/EXEC | systemd 219 模板 `%i` 未展开 | 使用 per-tool 单元 `ai-tool-fluorescence`（§6.2） |
| `import pycocotools` 成功但推理 ModuleNotFoundError | pycocotools 装在了 venv 但 YOLOX 路径未挂 | 同时检查 PYTHONPATH + pycocotools |
| torch import 报错 | 误装了 CUDA 版 torch（非 `+cpu`） | 确认 `torch==2.1.2+cpu` |
| pillow 版本不符（12.x 报错） | 未替换为 10.4.0 wheel | 检查主清单和 wheels/ |
| PDF 报告中文乱码 | 服务器无中文字体 | `yum install wqy-microhei-fonts` 或 tool.env 设 `REPORT_FONT_PATH` |
| 切端点报 422 | meta_json 的 `default_params` 传了多余字段 | `parameters` 是 `extra=forbid`，只给 part_id/device_id/timestamp |
| 推理极慢（>60s） | 图片过大或并发过高 | 确认 ≤20MB；`--workers 1` |

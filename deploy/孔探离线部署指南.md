# 孔探（Borescope）裸机离线部署指南

> **工具**：孔探叶片缺陷识别 (borescope)  
> **端口**：18014  
> **部署形态**：裸机 venv + systemd（**非容器**，wheel 为 manylinux_2_17，glibc 2.17 直接兼容）  
> **模型**：YOLOv8/v11 ONNX（压气机 compressor + 涡轮 turbine），CPU-only，onnxruntime 1.16.3  
> **目标环境**：x86_64 / Python 3.11.x / 中科方德 NFS Server 3.1 (glibc 2.17) 或 V4.0 (glibc 2.28)  
> **capability_id**：`borescope_defect_detection_v1`（平台 scene = `borescope`）

---

## 0. 为什么孔探不需要容器

孔探交付包全部 11 个 wheel 均为 `manylinux_2_17`（整包最高需求 glibc ≥ 2.17、GLIBCXX ≥ 3.4.19），
与 NFS Server 3.1 基线精确匹配。对比金相（manylinux_2_28 / torch 2.14 全栈需容器），孔探在裸机上
`install_offline.sh` 一步装完、`start.sh` 直接起服务。

**判定方法**（对新工具通用）：
```bash
cat /opt/agent/vision-agent/tools/borescope/requirements.lock | head -8
# 第 7-8 行写明门槛：glibc >= 2.17、GLIBCXX_3.4.19
```

## 3. 离线安装

### 3.1 拷贝交付包到服务器

```bash
# 从本地/U盘传到服务器（root 全程操作，不分用户）
scp -r Borescope_USB_Package/ root@<IP>:/opt/agent/vision-agent/tools/borescope/
# 或 rsync
rsync -av Borescope_USB_Package/ root@<IP>:/opt/agent/vision-agent/tools/borescope/
```

> ⚠️ 必须带上 `wheels/` 整个目录，否则安装无法进行。

### 3.2 执行安装

```bash
cd /opt/agent/vision-agent/tools/borescope
chmod +x scripts/*.sh
bash scripts/install_offline.sh
```

**脚本做了什么**（6 步，幂等）：
1. 校验 wheels/ 存在且含 .whl 文件
2. 严格校验 Python 必须是 3.11.x（**不做降级**，不通过则停止并输出需反馈的信息清单）
3. 在 `/opt/agent/vision-agent/tools/borescope/venv` 建虚拟环境（已存在则复用）
4. `pip install --no-index --find-links wheels/ -r requirements.lock`（**全程不联网**）
5. 自检 `import numpy / cv2 / onnxruntime`，打印版本和可用后端
6. 检查 models/ 下两个 ONNX 文件是否存在

**若 python3.11 不在 PATH**：
```bash
PYTHON_BIN=/usr/bin/python3.11 bash scripts/install_offline.sh
```

## 4. 停止 mock 服务（若端口被占）

首次部署时 18014 可能被演示 mock 占用。先确认再停：

```bash
# 1) 确认占用进程
ss -ltnp | grep 18014
# 或
lsof -i :18014

# 2) 确认是 mock 进程（命令行含 "main:app" 或 uvicorn）
PID=$(ss -ltnp | grep 18014 | grep -oP 'pid=\K[0-9]+')
tr '\0' ' ' < /proc/$PID/cmdline; echo

# 3a) 若由 systemd 管理（per-tool 单元 或 模板单元）
systemctl stop ai-tool-borescope 2>/dev/null || true
systemctl disable ai-tool-borescope 2>/dev/null || true
systemctl stop "ai-tool@borescope" 2>/dev/null || true

# 3b) 若直接进程（无 systemd），杀之
# kill $PID

# 4) 确认端口已释放
ss -ltnp | grep 18014 || echo "18014 已空 ✅"
```

### 5.2 systemd 前台托管（正式部署推荐）

交付包的 `start.sh` 是 nohup 后台模式，**不能直接给 systemd Type=simple 用**。  
正式上线须用**前台命令**做 ExecStart。先获取准确的前台启动命令：

```bash
# 前台直跑一次（手动 Ctrl+C 退出，确认命令正确）
/opt/agent/vision-agent/tools/borescope/venv/bin/python \
  /opt/agent/vision-agent/tools/borescope/app/api_server.py \
  --host 127.0.0.1 --port 18014
```

确认无误后，配置 systemd 单元（见 §6）。

### 5.3 自测（服务运行后执行）

```bash
./scripts/selftest.sh
# 三段检查全部 PASS 即可进入下一步：
#   [1/3] GET /health → 字段完整
#   [2/3] POST /api/v1/inference → 检出正常
#   [3/3] 错误码约定（6 个异常场景 + 2 个成功场景）
```

## 6. systemd 集成（生产常驻）

孔探使用平台统一的**模板单元** `ai-tool@.service`，实例名 `borescope`：

### 6.1 per-tool 单元（实际在 NFS 3.1 上的做法）

> 模板单元在 systemd 219 上有 `%i` 展开缺陷（见 ai-tools/README §6 记录），  
> 本机实际稳定运行的是**独立单元** `ai-tool-borescope.service`：

```bash
cat > /etc/systemd/system/ai-tool-borescope.service <<'EOF'
[Unit]
Description=AI tool: borescope (孔探叶片缺陷识别)
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/agent/vision-agent/tools/borescope
Environment=PYTHONUNBUFFERED=1
Environment=HOST=127.0.0.1
Environment=PORT=18014
ExecStart=/opt/agent/vision-agent/tools/borescope/venv/bin/python /opt/agent/vision-agent/tools/borescope/app/api_server.py --host 127.0.0.1 --port 18014
Restart=on-failure
RestartSec=5
StandardOutput=journal
StandardError=journal
SyslogIdentifier=ai-tool-borescope

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now ai-tool-borescope
systemctl status ai-tool-borescope       # 应为 active (running)
```

> **User=root 说明**：演示服务器全程 root 简化流程；若需隔离，改为 `User=borescope` 并 `chown -R borescope:borescope /opt/agent/vision-agent/tools/borescope`。

### 6.2 日常运维

| 操作 | 命令 |
|---|---|
| 启/停/重启 | `systemctl start\|stop\|restart ai-tool-borescope` |
| 查看日志 | `journalctl -u ai-tool-borescope -f` |
| 探活 | `curl -s http://127.0.0.1:18014/health` |
| 端口监听 | `ss -ltnp \| grep 18014` |

## 7. 验证真模型（指纹核验，勿只看 health 绿）

端口通 ≠ 真模型。必须看载荷指纹：

### 7.1 /health 指纹

```bash
curl -s http://127.0.0.1:18014/health | python3.11 -m json.tool
```

**真模型特征**：
```json
{
  "status": "healthy",
  "tool_name_en": "borescope",
  "tool_name": "孔探叶片缺陷识别",
  "tool_version": "1.0.0",
  "model_version": "v1.0",
  "model_loaded": true,
  "model_sha256_prefix": "6ABB1BFCB8DF4246...",
  "device": "cpu",
  "backend": "onnx"
}
```
关键字段：`model_loaded: true` + `model_sha256_prefix`（前 16 位与 MANIFEST 对照）+ 真实中文工具名。

### 7.2 /api/v1/inference 实打

```bash
curl -s -X POST http://127.0.0.1:18014/api/v1/inference \
  -F "image=@/opt/agent/vision-agent/tools/borescope/samples/000001.jpg" \
  | python3.11 -m json.tool
```

**真模型特征**：
- HTTP 200 + `code: 0`
- `count ≥ 1`（叶片缺陷至少检出一个框）
- `boxes[]` 内含 `category`（Dent/Tear/Deformation/Foreign matter 等）、`confidence`（0.25~1）、`bbox`
- 推理耗时 **几百 ms**（CPU ONNX），非 mock 的"即时返回固定 JSON"
- 返回含 `image_size`、`tool`/`tool_name` 等别名字段（超集设计）

## 9. 接口契约速查

| 项目 | 说明 |
|---|---|
| 接口 | `GET /health`、`POST /api/v1/inference`（仅此两个） |
| 入参格式 | 四种自动判别：原始字节 / multipart / JSON base64 / JSON data URI |
| `component` | `compressor`（默认）/ `turbine`（大小写与别名容错） |
| 推理参数覆盖 | 查询串 `?conf=0.25&iou=0.5&imgsz=480&backend=onnx&device=cpu` |
| 成功响应 | HTTP 200 + `code:0` + `count` + `boxes[]` |
| 失败响应 | HTTP 4xx/5xx + `{"error":"..."}` |
| 错误码 | 400 请求结构错 / 422 内容无法解图 / 404 未知路径 / 500 服务端内部 |
| 不使用的模式 | 不返回"HTTP 200 + code≠0" |

### 出参别名字段（超集设计，规范到手后可删）

| 主字段 | 别名 | 含义 |
|---|---|---|
| count | total | 检出数量 |
| boxes | results / detections | 检出框数组 |
| category | label / class_name | 缺陷类别 |
| confidence | score | 置信度 |
| bbox | bbox_xyxy / bbox_xywh / bbox_norm | 坐标（多格式） |

## 11. 故障排查速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `/bin/bash^M: bad interpreter` | 脚本被存成 CRLF（Windows 记事本另存） | `dos2unix scripts/*.sh` 或 `sed -i 's/\r$//'` |
| `no matching distribution found` | Python 不是 3.11.x | 安装 python3.11 或指定 `PYTHON_BIN` |
| `version 'GLIBCXX_3.4.22' not found` | libstdc++ 太旧，用了 1.19.2 | 改用 onnxruntime 1.16.3 |
| `libGL.so.1: cannot open shared object` | 误装了 opencv-python（非 headless） | 确认 wheels/ 内是 `opencv_python_headless` |
| 启动报 `unrecognized arguments:` | start.sh 被改回 `"${ARGS[@]:-}"` 空数组展开 | 用交付包原版 start.sh |
| multipart 报找不到图像文件 | boundary 被代码 `.lower()` 小写化 | 见 DEPLOY_NOTES §三（已修复，确认未改回） |
| 18014 无监听 | 进程启动失败 | 看 `logs/api_server.out` 末尾报错 |
| Address already in use | 旧进程未退出 | `./scripts/stop.sh`；或 `curl health` 确认是否仍在跑 |
| 日志 Permission denied | 目录属主与运行用户不匹配 | `chown -R $(id -un) /opt/agent/vision-agent/tools/borescope` |
| 推理极慢 | 非 CPUExecutionProvider | 确认 onnxruntime 后端自检输出 |
| /health 返回无 model_loaded | mock 未停干净 | 见 §4 彻底停 mock 后重启 |

孔探全流程不联网（`install_offline.sh` 用 `--no-index`），所以**纯内网部署零额外准备**：

**步骤与联网部署完全一致**（§2 → §3 → §5 → §6 → §7 → §8），无任何 pip 联网操作。

## 15. 附录：推理参数调优指南

| 参数 | 默认值 | 说明 |
|---|---|---|
| `conf` | **0.25** | 置信度阈值；默认 0.5 偏严容易漏检，实测 0.25 为最佳召回 |
| `iou` | 0.5 | NMS 重叠度阈值 |
| `imgsz` | **480** | 输入分辨率；调高反而降低召回率（模型训练基线 480） |
| `backend` | onnx | 推理后端（onnx / pt）；生产用 onnx（快且无 ultralytics 依赖） |
| `device` | cpu | 计算设备 |

配置在 `config/service.json` 的 `inference` 段，环境变量 `CONF`/`IMGSZ` 可临时覆盖。

**可视化调试**（排查"为什么检不出/为什么多框"）：
```bash
BLADE_DEBUG_DETECT=1 ./scripts/start.sh
tail -f logs/api_server.out
# 输出逐行显示：候选框数 → conf 过滤 → NMS 合并 → 最终检出
```

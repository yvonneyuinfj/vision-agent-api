# X光工具云服务器部署未成功 — 原因分析报告

- **报告日期**：2026-10-13
- **涉及环境**：公网云服务器验证环境（NFS Server 3.1，glibc 2.17），六工具裸机部署（`/opt/agent/vision-agent/tools/<tool>`，systemd `ai-tool@<tool>`，端口 18101-18106）
- **结论**：X光（DR）真实工具**未上线**，平台侧维持 mock 端点（`dr_defect_detection_v1`，18101）。根因为**交付 API 不符合《统一 API 接入规范 V1.0》，被打回返工**，叠加**依赖 wheel 与现网 glibc 基线不匹配导致装不上**，属双重阻塞。

---

## 一、背景

六工具（孔探 / 热端 / 荧光 / 金相 / X光 / 断口）由不同厂商分别交付，统一通过
`deploy/install_ai_tool.sh` 裸机安装、HTTP API 与 quality-agent 平台集成。
云服务器部署完成后，孔探、热端、荧光三个工具成功跑上真实模型并通过 E2E；
**X光未部署成功**，断口则因交付包缺失同样为 mock（原因与本项无关，单独催办中）。

## 二、根因分析

### 2.1 主因：接口不合规（需返工，🔴 阻塞级）

对照《动力所工业图像智能算法工具统一 API 接入规范 V1.0》，X光交付物
（`DRStructure_OPI_API_最终交付_20260914`）存在 3 处硬冲突 + 2 处卫生项：

| 类别 | 问题 | 违反条款 | 影响 |
|---|---|---|---|
| A. 输入契约 | `/api/v1/inference` 只接受专有 `.opi` 序列文件（`read_opi` 断言 2048×2048），不支持 JPEG/PNG/TIFF 标准图像 | §6 | 平台/前端发送的是单张标准图，**根本喂不进数据** |
| A. 输入契约 | 仅支持多帧 `images` 字段，无单张 `image` 字段 | §5.2 | 与平台现行调用方式不匹配 |
| B. 响应外壳 | 结果埋在 `data` 下，缺顶层 `result` / `tool` / `input` / `performance` | §7 / §7.1 | 平台只能用临时兜底 `transform_dr_structure`，不可长期依赖 |
| C. 产物取回 | `artifacts` 只给文件名，无可直接访问的 `uri`，需另调 `GET /api/v1/results/{request_id}/{name}` | §7.2 | 前端无法直接展示标注图/间隙图/报告 |
| D. 错误码 | "图像不合法"统一回 1001/422，未按 1002/415、1004/422、1001/400 拆分 | §8 | 卫生项 |
| F. 交付物 | 样例仅 `.opi`，无标准图像样例及一一对应的期望输出 JSON | §15 | 无法做合规回归验收 |

> 即便解决环境问题装上依赖，A/C 两类不解决则**既进不来也拿不走产物**，
> 依然接不进前端流程——这是"接口返工"与"装不上"两个独立维度的阻塞。

### 2.2 次因：运行环境基线不匹配（E类，🟠 阻塞级）

- 交付离线锁中 `pillow==12.3.0`、`contourpy==1.3.3` 为 `manylinux_2_27/2_28` wheel；
- 现网云服务器为 NFS Server 3.1（**glibc 2.17**），wheel 即使下载成功也会因 ABI 不匹配在 import 时崩溃；
- 解决路径二选一：
  1. 交付方提供 cp311 的 `manylinux_2_17/2014` 版本（如 pillow 10.4.0、contourpy 1.1.1）；
  2. 在填报表明确声明"最低 glibc 2.28"，待方德 V4.0 环境到位后部署。

两者阻塞性质不同，不应混谈（参见 `deploy/容器化离线部署指南.md` 开头的醒目提示）。

## 四、当时的处置

1. X光能力注册保持指向 **mock 端点**（18101，`dr_defect_detection_v1`），不阻塞平台整体演示；
2. 出具《X光接口返工单》（2026-10-05），以热端 API 实测返回为合规范例逐字段对照，发给开发方返工；
3. 平台侧保留 `transform_dr_structure` 临时兜底，明确标注不作为长期依赖；
4. Runbook 验收记录中如实登记「X光 mock（接口返工）」。

## 五、返工后回归验收标准

1. 用标准图像（png/jpg/tif）单张 POST `/api/v1/inference`，返回 §7 顶层外壳，`result.status` 为 `normal/abnormal`；
2. `artifacts[]` 每项 `uri` 可被 HTTP 直接取回；
3. 提供 cp311 `manylinux_2_17` 的 pillow/contourpy wheel，在 glibc 2.17 干净机 `import` 通过；
4. 错误输入分别命中 1002/415、1004/422、1001/400；
5. 附期望输出 JSON，与样例一一对应。

验收通过后：`install_ai_tool.sh dr` 安装就位 → `switch_tool_endpoint.sh` 将
`dr_defect_detection_v1` 从 mock 切至真实端点 → 跑 dr 场景 E2E 出结论。

# 2.2.6 大模型多智能体协同分析（重写版·基于实际工程实现）

> 本节依据 quality-agent 后端（Python / FastAPI / LangGraph）与 Vue 3 前端工程的真实代码重写，
> 所有组件名称、流程拓扑与交互机制均可在代码中逐一对应验证。

## 一、总体架构："双轨四图"多智能体协同体系

系统以大语言模型（LLM）为决策核心，基于 LangGraph 状态图框架构建了**双轨四图**的多智能体协同架构：

- **会话轨（对话智能体）**：面向用户的统一入口，负责意图理解、任务派发与结果播报；
- **任务轨（检测智能体）**：面向单次质检任务的执行体，按确定性程度分为三种形态。

| 图形态 | 智能体角色 | 决策方式 | 适用场景 |
| --- | --- | --- | --- |
| `session` 会话图 | 对话智能体（SessionAgent） | 极简 ReAct 循环（agent ⇄ tools） | 多轮对话、任务受理、进度问答 |
| `single` 固定流水线图 | 流程执行智能体 | 13 个确定性节点 + 条件路由 | 单场景标准质检（确定性优先） |
| `react` 自主图 | 自主检测智能体 | LLM 自主规划工具调用 + 出口安检 | 复杂/歧义输入、需自救重试的场景 |
| `joint` 联合图 | 联合调度智能体（父） + 子检测智能体 | 父智能体派发子任务、中断等待、唤醒聚合 | 多场景联合质检、逐级下钻 |

四种图共享同一套运行时基础设施：统一状态契约（AgentState，TypedDict 且全字段 JSON 可序列化，保证断点可持久化、全程可留痕）、依赖注入容器（启动时装配工具注册中心、LLM 服务、检查点存储、数据仓库为 AgentContext 下发给各节点）、以及 PostgreSQL/SQLite 检查点（checkpointer），支撑任务中断后的断点续跑与判重恢复。

## 二、各智能体的职责与协同机制

### 1. 对话智能体：理解意图，只负责"派活"和"播报"

会话图由 `session_agent` 与 `session_tools` 两个节点构成 ReAct 闭环：模型逐 token 流式输出（首字延迟即模型 TTFB），每一次工具调用（派发检测任务、检索知识库、查询任务进度等）以"活动流事件"的形式落到会话记录中，前端按"只推不改"契约渲染——历史消息一经产生不再变更，实时状态由流末尾的任务舱承载。对话智能体本身不做任何检测计算，检测一律下沉到任务轨，二者通过任务落定回调（`on_settled`）重新打通：子任务完成后，结果事件自动回注对应会话，用户无需刷新即可收到报告卡。

### 2. 场景路由：规则优先、VLM 兜底的三级判定

任务轨入口的 SceneRouter 按优先级依次判定检测场景：**结构化 scene 字段（前端"指定方向"显式标注）＞ 文件名/参数关键词规则（与六类能力场景对齐，含客户拼音命名约定）＞ 多模态大模型看图识别兜底**。高置信结果静默派发；识别出多候选歧义时不猜测，转入 `scene_confirm` 人工确认门（HITL），由用户点选场景后从断点继续，杜绝误选检测工具。LLM 不可用时自动降级为纯规则路由，流程不中断。

### 3. 固定流水线智能体：确定性八段主链 + 两道人工门

`single` 图以纯确定性节点串联完整质检链路：

```
select_capability → resolve_capability → validate → invoke_capability
→ normalize_result → rag_retrieval → grading →（explain_metrics）→ generate_report
```

- **invoke_capability**：经工具注册中心按名称取用算法工具，实际调用下沉到能力适配层（HTTP 适配器对接六类算法工具 API，另备 mock / 离线桥接 / 模型服务适配器），支持孔探、红外热图、X 射线 DR、荧光渗透、金相、断口六类场景；
- **normalize_result**：六类工具输出格式各异，统一归一化为标准缺陷结构（含置信度、严重度聚合策略）；
- **rag_retrieval + grading**：先检索标准/规程知识，再由规则引擎（grade_rules.yaml）做出 pass / defect / review / fail 四级判级——**判级终裁权始终掌握在确定性规则手中，不交由大模型自由裁量**；
- **human_review（HITL 复核门）**：判级为 review/fail 时，图通过 interrupt 原语暂停，任务置为"待复核"，断点状态由检查点持久化；质检人员提交复核结论后以 Command(resume) 从断点精确续跑至报告生成。复核支持通过、驳回与修订三种动作，修订可携带全量缺陷清单并保留溯源 diff 痕迹。

任一节点失败均不使图崩溃：错误统一收敛到 `state['error']`，路由至 `explain_error` 节点生成可读的失败解释后优雅收尾。

### 4. 自主检测智能体："自主区 + 安检区"双区设计

`react` 图将大模型真正用作决策者：模型在 `react_agent` 节点自主规划下一步动作，可用工具箱收敛为三个工具——`invoke_capability`（场景检测，返回前自动完成结果标准化）、`retrieve_knowledge`（知识检索）、`submit_final`（提交结论）。为防止 LLM 幻觉污染质量结论，架构上划出明确的**安检区**：

- 判级终裁、人工复核门、报告骨架**强制复用固定流水线的确定性节点**，运行时不可绕过；
- `exit_gate` 出口安检节点校验提交的完备性（拒检/证据不足直接拦截）；
- 能力调用预算封顶（默认 3 次，含自救重试），超限即收敛，杜绝无限循环烧算力。

即"让模型自由探索过程，但结论出口全部走确定性闸门"——兼顾智能化与环境适应性，又守住质量判级的严肃性底线。

### 5. 联合调度智能体：父子任务的中断-唤醒协同

`joint` 图处理多场景联合质检：父任务本身是一个 ReAct 自主智能体，按业务规则（调用顺序 + 下钻条件）决定先做哪个场景、上一场景的输出是否触发下一场景的逐级下钻；它通过联合工具箱派发子任务（每个子任务即一次独立的单场景检测图执行），随后调用 `await_children` 使父图 interrupt 暂停挂起。**子任务落定事件驱动父图唤醒**：完成/失败/待复核均视为落定（待复核子任务不阻塞父图，父智能体在结论中如实标注），多个子任务近乎同时落定时由父任务唤醒锁串行化判定，避免重复唤醒。全部落定后父图续跑，聚合各场景结论生成联合报告。

## 三、前端协同呈现（Vue 3 + TypeScript 工程）

前端将后端多智能体的协同过程转化为可观察、可介入的人机交互：

- **首页对话式受理**：上传图像 + 自然语言描述即可发起检测，支持"指定方向"下拉显式声明场景（拼接为后端可解析的标注文本，参与三级路由）；
- **检测页活动流 + 任务舱**：智能体每一步思考与工具调用以事件行落入活动流（只推不改），任务实时进度以独立"任务舱"卡片呈现在流末尾，StageStepper 将后端节点进度归一为六段阶段展示（前端轮询）；
- **人工复核工作台**：ReviewDecisionPanel 承载复核三动作，ReviewDefectTable 支持全量缺陷修订（每项含 defect_type，后端整单校验），GradeStamp 将判级结论统一印章化呈现；
- **报告与终态反查**：报告卡支持弹窗查阅，任务以终态卡关闭运行卡（终态反查模式），保证会话与任务两侧状态一致。

## 四、一次典型的端到端协同链路

以"这批叶片先做荧光渗透，若有显示再用孔探确认裂纹形态"为例：

1. 用户在会话中上传图像并输入诉求 → **对话智能体**解析意图，调用派发工具创建联合检测任务，活动流出现受理行；
2. **联合调度智能体**（父图）派发"荧光渗透"子任务 → 子任务走单场景流水线：场景路由命中 fpi → 调用渗透检测算法工具 → 结果归一化 → RAG 检索验收标准 → 规则判级；
3. 判级 defect，命中下钻条件 → 父智能体再派发"孔探"子任务，随后 `await_children` 挂起；
4. 孔探子任务判级 review → 暂停进入**人工复核门**，前端复核工作台弹出，质检员修订缺陷清单后恢复；
5. 全部子任务落定 → 父图唤醒，聚合两场景结论生成联合报告 → `on_settled` 回注会话，前端任务舱置终态、报告卡落入活动流。

全程每一步（模型思考、工具调用、规则判级、人工介入）均以检查点形式持久化留痕，可审计、可断点恢复。

## 五、工程保障

- **可靠性**：节点级错误统一收敛、LLM 故障自动降级为规则路径、检查点断点续跑（图结构指纹判重）；
- **可扩展性**：新增算法工具仅需实现统一 Tool 抽象并注册，配合归一化器与判级规则、路由关键词更新，图结构零改动；
- **可评测性**：内置期望集评测脚本与分层测试（节点/图/API/能力层），CI 流水线自动回归，LangGraph Studio 支持图级可视化调试。

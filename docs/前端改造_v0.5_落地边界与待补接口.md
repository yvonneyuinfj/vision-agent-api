# 前端改造 v0.5 · 落地边界与待补接口

> **批次 1–2 的硬约束**：不新增、不修改任何后端接口 / 响应模型 / 数据库列，只使用已存在的端点（实施计划 §6）。

## 表 A · 已落地页面 ↔ 实际调用的接口

「窗口口径」列是页面上真实呈现的数据边界——它决定了该页能声称什么、不能声称什么。

**场景条目的取数口（决策 52）**：首页场景卡、运行监控场景卡、`/detect/:scene` 工作台、`/tasks/new` 场景选择、`/tool/registry` 场景下拉五处统一由 `GET /scenes` 提供（`frontend/src/hooks/useScenes.ts`：模块级缓存，读取失败或返回空数组时回退内置 `constants/workbench.ts` 六条）。下表各行写出的场景键是**当前目录的内容**，不是页面的硬编码上限；新增场景＝后端 `app/services/scene_catalog.py` 加一条，前端无需改动。侧栏「智能检测」下的工作台叶仍取内置表（每叶需逐个配图标，目录新增场景在导航里回退 `flask`），这是**已知且有意**的兜底差异。目录里 `auto_recognize=false` 的场景只能人工显式选场景提交——自动识别的关键词表与 VLM 提示词仍只认六键（见实施计划 决策 52 ③）。

### A5 页面文案边界：长公告一律移出页面（决策 51-⑦/⑨）

页面只保留内容本身与**就近提示**（表单字段 hint、启停二次确认的后果文案、表格上方一行统计脚注）。
原先挂在 `/tool/registry`、首页与各页分页条上的治理口径全文搬到这里，**改口径改本节，不改页面**：

**① 写侧口径**：登记 / 编辑 / 启停 / 试运行已按 `POST · PATCH · POST /{id}/status · POST /dry-run` 做实，每次写入都必填**变更原因**并落 `meta_json.change_log`；「重新加载」只是让后端**重读**注册表。变更原因必填、操作人自报（留空取登录会话用户名），**未做角色授权与前后值审计**（G4-01）；请求头只在读方向回掩码（键名 + 末 4 位），**密钥托管与轮换属 G4-03**，本轮不实现。

**② 注册工具 ≠ 新增工作台**：工具按 **scene 路由键**挂到场景目录（`SCENE_CATALOG`，当前六条；决策 52 已落地，条目由 `GET /scenes` 下发）之一，同一场景可挂多个工具（候选歧义时由任务链的 `scene_confirm` 人工确认门收窄；同场景多条已启用时按**登记序取首条**），换工具版本也不动侧栏。**能力 ID 与工具名创建后不可改**，换身份＝新建一行 + 停用旧行；端点或请求头变更须凭一次成功**完整试运行**的回执快照（回执只在后端进程内有效，**重启或 30 分钟后须重跑**；「测试连通性」不发放回执），**干跑未过不得置为已启用**。"每工具每环境一个默认 ACTIVE 版本"的切换与回滚属 G3-05，见 `/tool/model-versions` 壳页说明。

**③ 首页「本轮不做的能力」公告**（决策 51-⑨ 从首页底部移出）：原文为"本轮不做的能力（后端接口不存在）：任务取消 · business_ref 跨任务聚合 · 按时间/创建人筛选 · 原始工具输出查看 · 模型工坊全链路"。这五项**在本节下方的表 B 逐条在册**（取消 → G1-02；business_ref 与按时间/创建人筛选 → 任务业务元数据 / 列表筛选两行；原始工具输出查看 → 工具原始响应可查；模型工坊全链 → 零接口），首页不再重复挂公告；**新增或取消一项只改表 B**。


**④ 窗口口径脚注与页内场景切换行**（决策 51-⑪ 从页面移除，原文在此留底）：

## 偏差说明（与批次 1 原型有意不同）

1. **`/tasks/samples` 的"缺陷类别分布"改口径**：原型按六类缺陷展示，但接口侧无按缺陷类别聚合的计数（`review-matrix` 只给聚合矩阵与 `low_confidence_band`）。现改为由 100 条窗口内任务的 `standardized` **缺陷修订差异**（复核前 → 复核后）统计，页面直述该口径。全量、按类别的服务端聚合属表 B 的 G3-01（候选池）与 FR-PRO-006（专业统计，无工作包编号）。
2. **工作台页头部无 `page-title`**：与原型一致，各专业工作台以场景条（`.scenebar`）起头而非 `page-head`，故 e2e 导航断言的标题选择器取 `.page-title, .scenebar`（`frontend/e2e/specs/nav.spec.ts`）。
3. **工具服务中心由 5 叶收敛为 4 叶**（决策 24）：原型的"工具注册"与"工具版本"两页在接口上是同一份 `GET /capabilities` 的两种切法，合并为「工具注册与版本」单页 9 列，`/tool/versions` 只留重定向。
4. **助手页无"对话 / 思维链"页签**（决策 25）：原型的两页签在方案 v0.5 全文无对应条款（"思维链/思考链"零命中），且会把一条 SSE 流的卡片切开，故合并为同流呈现。
5. **「样例与指南」删除快捷键区块**（决策 26）：键盘快捷键既无接口也无方案依据，页面只留三组内置指引（标准流程 / 判定口径 / 结果与报告约束）。

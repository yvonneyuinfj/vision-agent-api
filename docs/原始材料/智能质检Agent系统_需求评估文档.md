# 智能质检 Agent 系统需求与建设成本评估文档

> 版本 V1.0 ｜ 2026年8月  
> 用途：明确本期建设范围、开发内容、集成边界和实施条件，为工作量估算、开发成本测算及交付评估提供依据。

---

## 0. 文档范围

本期面向高端装备工业图像检测场景，建设智能质检 Agent 系统，打通任务提交、检测模型调用、结果标准化处理、知识检索、辅助判级、报告生成、人工复核和过程追溯。

本次评估重点回答三个问题：

1. 本期需要开发哪些智能体能力、业务流程和配套模块；
2. 各检测模型、知识源和客户环境需要满足哪些接入条件；
3. 各项开发工作的复杂度、工作量和成本如何测算，计划周期内交付还存在哪些依赖。

---

## 1. 项目概述

### 1.1 项目背景

某高端装备制造客户需要对关键部件开展多场景无损检测和失效分析，涉及孔探、红外成像、高能 X 射线（DR）、荧光渗透、断口与金相组织分析五类场景。

专业检测模型由多家合作方分别研发，当前存在三类接入形态：HTTP API、模型文件和本地软件。各模型的输入条件、输出结构、严重度标准和成熟度也不一致，无法由上层系统直接统一调用。

现有检测结果以缺陷识别和定量测量为主，与判级标准、历史报告和期刊资料之间缺少自动关联。本期系统需将模型结果与本地知识库结合，为检测人员提供有依据、可复核的辅助判读结果。

### 1.2 建设目标

| 目标 | 本期目标说明 |
|------|-------------|
| 统一调度 | 根据检测场景和输入条件选择对应模型，屏蔽底层接口差异 |
| 接口适配 | 通过适配层接入 HTTP API、模型文件服务和本地软件 |
| 结果标准化 | 按缺陷检测、定量测量、模式分类三类结果分别处理，不强行套用同一结构 |
| 知识增强 | 根据检测方法、缺陷类型和测量参数检索本地资料，生成依据说明 |
| 人工复核 | 对高严重度、低置信度或规则无法覆盖的结果转人工确认 |
| 全程追溯 | 保留原始数据、模型版本、调用参数、知识来源、报告版本和复核记录 |
| 私有化部署 | 外部环境用于开发联调，业务数据和知识资产最终部署在客户内网 |

### 1.3 角色分工

| 角色 | 主要职责 |
|------|---------|
| 客户 | 提供业务规则、知识资料、算力与部署环境、测试数据和领域专家；组织验收 |
| 合作方 | 交付检测模型及配套资料，配合接口联调和问题定位 |
| 我方 | 负责总体设计、平台建设、模型接入、知识增强、流程开发、部署迁移和验收支持 |

### 1.4 计划周期

项目按 4 个月安排，目标在 11 月前完成验收。前 3 个月完成开发和联调，第 4 个月完成内网部署、试运行和验收。具体起止日期需结合资源开通时间、模型到位时间和客户内网条件进一步确认。

## 2. 业务范围与流程

### 2.1 检测场景

| # | 场景 | 典型输入 | 主要输出 |
|---|------|---------|---------|
| 1 | 孔探损伤检测 | 可见光内窥镜图像或视频帧 | 缺陷类别、位置、置信度、严重度 |
| 2 | 热端部件红外成像 | 红外热图、辐射值 CSV | 缺陷类别、位置、置信度、严重度 |
| 3 | 高能 X 射线（DR） | 数字影像、参考图及标定信息 | 结构区域、关键点、偏移测量、趋势曲线 |
| 4 | 荧光渗透检测 | 紫外荧光图像 | 裂纹或点状缺陷、位置、面积、长度 |
| 5 | 断口与金相分析 | 光学或电镜图像 | 组织相统计、晶粒度、断裂模式 |

> 专业检测模型由合作方提供。本期建设范围是模型接入、任务编排、结果处理、知识增强和业务闭环，不包含检测模型训练。

### 2.2 端到端流程

```text
提交检测任务和输入数据
        │
        ▼
识别场景并校验必填输入
        │
        ▼
查询能力注册中心，选择并调用检测模型
        │
        ▼
按结果类型进行标准化处理
        │
        ▼
检索本地知识库，生成解读和引用依据
        │
        ▼
按业务规则辅助判级
        │
        ├─ 满足自动处理条件：生成报告
        └─ 高风险或低置信度：人工复核后生成报告
        │
        ▼
报告归档和全链路留痕
```

场景明确时优先采用业务规则路由，避免完全依赖大模型判断。仅在场景不明确或需要补充理解时，使用多模态模型提供候选结果，并由规则或人工确认。

### 2.3 业务模式

- **单场景质检**：一次任务调用一类检测能力，完成结果标准化处理、知识解读和报告输出。
- **多场景联合质检**：针对同一部件按业务条件逐级调用不同检测能力，汇总形成部件级结论。检测顺序和下钻条件由客户提供的业务规则确定。

## 3. 待集成能力与约束

### 3.1 模型现状

| # | 模型能力 | 场景 | 提供方 | 当前形态 | 主要约束 |
|---|---------|------|--------|---------|---------|
| 1 | 孔探损伤检测 | 孔探 | 合作方 A | 模型文件，可提供容器 | 需封装服务；运行资源要求较高 |
| 2 | 红外故障识别 | 红外成像 | 合作方 B | HTTP API | 需同时输入图像和辐射值 CSV；可用时间及算力待确认 |
| 3 | 结构识别与偏移测量 | X 射线（DR） | 合作方 C | 本地软件 | 暂无标准 API；依赖参考图和标定信息 |
| 4 | 荧光缺陷检测 | 荧光渗透 | 合作方 D | 模型文件，接口待确认 | 需确认最终交付形态和测量口径 |
| 5 | 组织识别检测 | 金相组织 | 合作方 E | HTTP API | 属于定量分析，不适用通用缺陷严重度 |
| 6 | 断口识别检测 | 断口分析 | 合作方 E | HTTP API | 主要输出断裂模式，无定位和严重度信息 |

### 3.2 接入约束

1. **接口不同**：HTTP API 可直接适配；模型文件需封装为服务；本地软件需建设文件或进程桥接能力。
2. **输入不同**：红外场景依赖辐射值 CSV，X 射线场景依赖参考图和标定信息，调用前必须校验。
3. **输出不同**：系统需分别处理缺陷检测、定量测量和模式分类结果，不能使用单一响应结构覆盖全部场景。
4. **严重度不同**：有严重度输出的模型按客户规则映射；无严重度的结果保留原始指标，由业务规则综合判断。
5. **到位时间不同**：主链路应优先使用已具备条件的模型验证，未按期到位的模型在其交付后补充接入。

### 3.3 合作方最低交付要求

每个模型接入前应提供：

- 模型名称、版本、适用场景、支持的缺陷或指标；
- 输入格式、尺寸要求、必填元数据和有效样例；
- 输出字段、单位、坐标含义、置信度和严重度说明；
- 服务或模型文件、依赖环境、算力要求及启动方式；
- 并发上限、超时建议、错误码和健康检查方式；
- 测试样本、预期结果及联系人。

建议将上述信息固化为 `model_manifest`（模型能力描述文件），作为模型准入、调度、版本管理和审计的统一依据。

## 4. 总体能力架构

| 层级 | 本期职责 | 建设内容 |
|------|---------|---------|
| 交互层 | 任务提交、状态查看、报告查看、人工复核 | 默认前端及标准服务接口 |
| 编排层 | 场景路由、输入校验、流程控制、辅助判级、报告生成 | 智能体编排平台及业务流程 |
| 接入层 | 模型注册、接口适配、调用治理、结果标准化处理 | AI 网关、适配器、能力注册中心 |
| 知识层 | 资料入库、检索、引用和权限控制 | 本地知识库、文档解析、页面采集 |
| 模型层 | 通用语言和图像理解能力 | 客户环境内的大模型服务 |
| 资源层 | 检测模型和业务知识资料 | 合作方模型、标准、报告和授权资料 |

编排层不直接绑定具体检测模型。模型和知识源的新增、更新与停用通过能力注册中心和知识库配置完成，避免频繁修改主流程。

## 5. 建设能力要求

本章只列本期开发直接涉及、影响工作量和成本的能力。后续测算需说明复用现有能力、配置实现、适配开发或专项开发的范围及依据。

### 5.1 智能体编排平台

| 本期能力 | 要求 |
|---------|------|
| 任务与流程编排 | 支持串行、并行、条件分支、超时和失败处理，可配置单场景及多场景流程 |
| 工具调用 | 可调用 HTTP API、标准工具协议和自定义工具，并传递文件、结构化参数及上下文 |
| 业务逻辑扩展 | 支持通过代码或扩展节点实现输入校验、结果标准化处理、规则判断和报告组装 |
| 调试与回放 | 可查看节点输入输出、错误信息和执行链路，支持按任务重放或定位问题 |
| 状态持久化与恢复 | 长任务或异步任务中断后可查询状态并继续处理，避免重复调用模型 |
| 人工复核 | 可在指定条件下暂停流程，记录复核意见后继续、退回或重新生成 |
| 运行追溯 | 按任务查询模型调用、知识检索、规则判断、报告生成和人工操作记录 |
| 服务化与私有化 | 可发布标准接口，并支持容器化部署和跨环境迁移 |

`Plan-Execute-Express-Review`（计划—执行—表达—复核）可作为流程职责划分方式，实际开发可根据现有技术基础采用等效实现。

#### 5.1.1 本期定制流程

1. 单场景质检流程，包括输入校验、模型调用、知识检索、辅助判级和报告输出；
2. 多场景联合质检流程，包括调用顺序、下钻条件和结果汇总；
3. 能力注册中心及 `model_manifest` 管理；
4. 缺陷、测量和分类三类结果的标准化处理；
5. 严重度映射和业务规则配置；
6. 报告生成、引用定位和版本留痕；
7. 高风险或低置信度结果的人工复核闭环。

### 5.2 AI 网关与适配层

| 本期能力 | 要求 |
|---------|------|
| 统一接入 | 统一代理检测模型、知识检索和本地软件桥接能力 |
| 异构接口适配 | 支持 HTTP API、模型文件服务和本地软件三类接入方式 |
| 任务调用 | 支持同步和异步调用、状态查询、超时、有限重试和结果回收 |
| 稳定性控制 | 支持鉴权、并发限制、限流、熔断、健康检查和错误隔离 |
| 调用追踪 | 记录任务标识、模型版本、请求时间、结果状态、耗时和错误信息 |
| 私有化部署 | 支持 Docker/K8s 部署，配置可从联调环境迁移至客户内网 |

三类接口的处理方式如下：

| 接口类型 | 对应能力 | 本期处理方式 |
|---------|---------|-------------|
| HTTP API | 红外、组织识别、断口识别 | 适配现有接口并注册为统一工具 |
| 模型文件 | 孔探、荧光 | 封装为容器化推理服务后接入网关 |
| 本地软件 | X 射线 | 本期优先采用文件投放与结果回收桥接；标准接口改造由相关方另行确认 |

### 5.3 知识库与页面采集

| 本期能力 | 要求 |
|---------|------|
| 多源入库 | 接入授权范围内的期刊、内部报告、判级标准和维修资料 |
| 文档解析 | 解析常见文档中的标题、正文、表格和图片文字；保留页码及来源信息 |
| 清洗与切分 | 去除页面噪声和重复内容，按文档结构或语义切分 |
| 检索与排序 | 支持关键词和语义混合检索，并对候选结果进行重排序 |
| 元数据与权限 | 按来源、资料类型、业务域和敏感级别管理及过滤 |
| 引用溯源 | 输出可定位到来源文档、页码、段落或条目的引用信息 |
| 增量更新 | 资料变化后可增量解析、建索引并保留更新记录 |
| 私有化部署 | 原文、索引、检索服务和日志均保留在客户环境内 |

客户内网页面无开放接口时，需要建设授权范围内的页面采集能力：

- 按客户确认的范围采集页面内容和元数据；
- 保留来源地址、采集时间和更新状态；
- 采集与解析分离，页面结构变化时可单独调整解析规则；
- 支持频率控制、失败重试、增量更新和异常记录；
- 授权范围、使用范围和版权边界由客户确认。

### 5.4 大模型

大模型用于任务理解、场景辅助识别、检索条件生成、指标解读和报告撰写，不替代专业检测模型及客户判级规则。

| 能力 | 本期要求 |
|------|---------|
| 文本能力 | 根据结构化检测结果和检索资料生成解读及报告 |
| 多模态能力 | 在场景不明确时提供图像理解和候选场景，不直接作为最终检测结论 |
| 部署要求 | 部署在客户提供的算力环境，推理数据和日志不出域 |
| 效果评估 | 按客户确认的测试集、指标定义和验收方法评估；具体准确率目标另行确认 |

### 5.5 前端与接口

| 能力 | 本期要求 |
|------|---------|
| 任务提交 | 上传图像及配套数据，校验必填项并创建任务 |
| 状态查看 | 查看排队、执行、待复核、完成和失败状态 |
| 报告查看 | 展示检测结果、指标解读、引用来源和报告版本 |
| 人工复核 | 支持确认、退回、填写意见和重新生成 |
| 历史查询 | 按任务、时间和场景查询历史记录 |
| 系统接口 | 提供标准服务接口，便于后续对接客户现有系统 |

## 6. 集成与责任边界

| 事项 | 责任方 |
|------|-------|
| 智能体编排平台、AI 网关和知识库 | 我方负责基础能力建设、配置、定制开发和交付 |
| 检测模型及模型质量 | 合作方负责交付，我方负责接入和调用验证 |
| 模型文件服务化 | 我方封装，合作方提供完整运行依赖和技术支持 |
| X 射线本地软件桥接 | 我方建设本期桥接，合作方配合明确输入输出和运行机制 |
| 判级规则和严重度映射 | 客户业务专家提供并确认，我方转化为系统规则 |
| 知识资料及采集授权 | 客户提供资料并确认授权和使用边界 |
| 指标解读和引用核对 | 客户业务专家参与确认，我方实现系统流程 |
| 算力、网络和内网环境 | 客户提供，我方提出配置要求并完成部署 |
| 测试、迁移和验收支持 | 我方组织实施，客户和合作方按职责配合 |

系统输出属于辅助判读结果。最终判定责任及自动处理边界应由客户结合业务制度确定。

## 7. 实施路径与里程碑

### 7.1 实施安排

| 阶段 | 周期 | 主要工作 | 完成标志 |
|------|------|---------|---------|
| M1 | 第 1 月 | 部署基础组件；确定统一接口和 `model_manifest`；接入已就绪的 HTTP 模型；启动页面采集预研 | 基础环境可用，首个模型调用链路打通 |
| M2 | 第 2 月 | 封装模型文件；建设能力注册中心和结果标准化处理模块；预研本地软件桥接；打通知识增强链路 | 至少一个单场景流程端到端可用 |
| M3 | 第 3 月 | 接入已到位模型；配置联合流程和判级规则；完成外部环境整体联调 | 约定范围内的功能通过联调测试 |
| M4 | 第 4 月 | 内网部署迁移；配置权限、观测和留痕；开展试运行和验收 | 内网系统可用并完成约定验收 |

红外等尚未确认交付时间的模型不作为前期主链路的唯一依赖。若模型未按约定时间到位，应采用模拟服务或已就绪模型验证平台能力，并单独评估对最终验收范围的影响。

### 7.2 主要风险与应对

| 风险或依赖 | 可能影响 | 处理建议 |
|------------|---------|---------|
| 模型及接口未按期交付 | 压缩联调和测试时间 | 交付前置，按模型设置最晚到位时间；准备模拟服务 |
| 本地软件缺少标准接口 | 桥接开发和稳定性验证工作量较大 | 第 1 月完成技术预研，尽早明确文件和进程机制 |
| 严重度和输出口径不统一 | 增加数据转换、判级和报告解释的开发工作 | 尽早确认字段、单位、映射规则和例外处理 |
| 页面结构或访问策略变化 | 影响知识采集稳定性 | 采集与解析解耦，保留失败记录和规则调整能力 |
| 联调环境与内网差异 | 迁移时产生返工 | 提前核对网络、算力、操作系统、依赖和安全策略 |
| 业务规则或验收集不完整 | 无法验证辅助判级效果 | 在开发早期冻结首版规则、样例和验收口径 |
| 4 个月内并行工作较多 | 对人员到位和协作效率要求高 | 模型接入、知识链路和部署准备并行推进，按阶段验收 |

## 9. 评估与确认事项

### 9.1 开发范围评估

围绕第 5 章梳理本期需要实现的模块和流程，并按以下口径划分：

- 直接复用：现有基础能力可直接使用，主要工作是部署和联调；
- 配置实现：通过流程、规则或参数配置完成；
- 适配开发：针对模型接口、数据结构或客户环境进行改造；
- 专项开发：需要新增模块、业务流程或交互功能。

评估时应分别说明实现方式、前置输入、开发边界和验收标准，作为工作量及成本测算依据。重点拆分私有化部署、异构模型接入、异步任务、结果标准化处理、人工复核、链路追踪、复杂文档解析、引用定位和内网页面采集。

### 9.2 工作量测算

工作量应至少拆分为：

1. 三类基础组件的部署和配置；
2. 各模型接入、模型文件服务化及本地软件桥接；
3. 能力注册中心、结果标准化处理和判级规则；
4. 单场景及多场景流程；
5. 页面采集、文档解析、知识入库和检索调优；
6. 报告、引用溯源和人工复核；
7. 前端与系统接口；
8. 测试、内网迁移、试运行和验收支持。

测算时需列明假设条件，避免将合作方模型改造、客户数据整理或规则编制工作计入我方默认范围。

### 9.3 费用测算

费用测算以智能体开发和实施成本为主，建议区分基础能力部署、模型接入与适配、业务流程开发、知识工程、前端与接口、内网迁移、测试验收及后续运维。若涉及第三方授权、原厂支持、算力、存储或网络资源，应单独列为外部成本，不与开发成本混算。

### 9.4 交付可行性

4 个月计划能否成立，取决于以下条件：

- 基础环境和核心人员按期开通、到位；
- 首批模型及配套资料在 M1 到位；
- 本地软件桥接方案在 M1 完成验证；
- 客户及时提供知识资料、业务规则、测试数据和专家支持；
- 内网部署条件在迁移前完成准备；
- 验收范围、测试集和判定口径在联调阶段前确认。

### 9.5 待确认清单

- 项目正式起止日期及 11 月前验收的具体时间点；
- 各模型交付时间、最终接口形态、样例和运行资源；
- 红外模型是否纳入本期最终验收及其替代联调方案；
- X 射线桥接允许的技术方式和运行权限；
- 严重度映射、联合判定规则、人工复核条件和最终责任边界；
- 知识资料范围、内网页面访问方式、采集授权和版权边界；
- 用户数量、并发量、数据规模、性能目标和数据保留周期；
- 测试集、验收指标、报告模板和验收流程。

# 工业图像智能检测智能体 —— 需求对齐差距分析与人力资源评估

> 依据材料：
> - `docs/原始材料/工业图像智能检测智能体需求说明书.docx`（下称"需求说明书"，一期建设口径）
> - `docs/原始材料/ui设计.png`（首页高保真设计图，1672×941）
> - 当前代码库（AeroQC 智能质检 Agent 系统，2026-09 快照）
>
> 结论速览：**当前项目约覆盖一期需求的 40%**（单工具检测主链路、多场景联合质检轨、能力注册、知识检索、HITL 复核、报告雏形、会话助手均已端到端可用）。对齐改造的主要缺口集中在：**六类专业工作台、任务中心业务对象（批次/零件/执行记录）、能力中心（Skill/模板/数据集）、运行管理（环境/发布包/部署实例）、系统管理（用户权限/字典/审计）、首页重设计、综合智能检测产品化、内网私有化部署**八大块。总投入估算 **300~430 人日（约 14~21 人月）**，建议 **6~8 人团队、4~5 个月**完成一期范围。

**明确不满足的关键点（抽查发现）：**
- FR-RUN-003「重新执行不得覆盖原始执行记录」：当前 `POST /tasks/{id}/retry` 为**同 thread 原地重跑**，覆盖旧记录 → 需引入独立 Run（检测执行）实体。
- FR-SYS-001~005：**全库无任何认证/用户/角色/权限/字典/审计代码**（前端用户"王逸清"为硬编码）。
- 非功能-安全保密：当前 LLM 走公网 DashScope → 内网交付必须切换私有化 LLM（Provider 注册表已预留，属部署+联调工作）。

2. **缓**：Skill 体系一期只做注册+启停+调用日志（插件化生态二期）；运行管理只做登记查询（自动化流程二期，与需求书"扩展预留"一致）；MCP 随 C-05 确认结论决定一期深度。
3. **砍不得**：Run 不覆盖重跑、三层结果分离、版本追溯链、审计——这些是需求书验收口径的硬条目。

## 6. 结论

当前项目已有一条质量较高的"单工具智能检测 + 多场景联合"主干（编排、网关、知识、复核、追溯），与需求说明书的**理念与架构分层高度兼容**，不需要推倒重来；对齐改造本质是**从"检测流水线"升级为"平台"**：补业务对象模型（批次/Run/模板/Skill/数据集/环境/发布包/实例/用户权限）、将联合编排产品化（模板驱动、工具集确认、汇总分层）、补六类专业工作台、按 UI 设计图重建首页与导航。

**总投入：300~430 人日（14~21 人月）；建议 7~8 人团队（PM/架构 1 + 后端 2~3 + 前端 2 + 集成 1 + 测试 1 + UI 0.5），工期 4~5 个月**，其中前 3 个月完成开发、第 4~5 个月内网部署+联调+验收。若客户工期压至 4 个月内且验收范围不裁剪，需 8~9 人满配并行并承受联调风险；若接受范围裁剪（§4.3），6~7 人 4 个月可交付保优先级版本。
